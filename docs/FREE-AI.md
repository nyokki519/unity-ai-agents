# 無料AIによる日次提案

設計: 既存の日次Analytics取得が成功した後、固定のWorkers AIモデルで非個人の全体集計から最大3件の改善案を作る。任意のタスク指示、イベント名/ID、候補の自由文、個人情報、秘密値は送らない。出力はJSON/Zodで検証して未検証の提案として表示するだけで、実行計画や権限には変換しない。

無料条件: Workers Freeを所有者が確認済み。公式pricingでFree1日10,000 Neurons・超過時エラーを確認済み。モデルは@cf/meta/llama-3.1-8b-instruct-fp8-fast固定、UTC1日最大1試行（失敗含む）、入力6000文字以下、出力max_tokens1024。Paid切替/有料fallbackなし。アカウント全体の残枠は未知で、枠不足は停止する。

安全性: 完全で36時間以内のデータのみ。日次claim/試行数をStateへ永続化し、再起動/重複起動で増殖しない。stopCount/元snapshot取得日時を結果保存時にも照合する。タイムアウト25秒、当日自動再試行なし。失敗の生例外は保存しない。過去の実行待ちタスクや重要操作は進めない。

検証対象: データ投影、1日上限、古さ/失敗/不明、未設定、停止/再開、遅延応答、JSON不正/余計なフィールド、モデル固定と出力上限、保存/再起動。実モデルの成功は本番API/実行記録で別途確認する。

## 実装した動作
日次取得成功後にAI bindingがある場合だけ起動する。初期の未設定・古い/部分/時刻不明のデータ・停止では推論しない。分析待ちに停止APIが処理できるよう内部の定期経路は全リクエストのmutexを保持せず、各State transactionと結果保存時のfenceで保護する。

生成結果はダッシュボード「AI改善案」に表示。任意の手動指示の引継ぎは従来通り。タスクの自動完了・外部送付・コード変更はしない。最新1回だけ保持し、データ取得日時と未検証の表示を付ける。停止/データ変更による保留、provider失敗、不正出力、timeoutを安全なコードで記録する。

usage.aiCallsは予約済み試行数（失敗/timeout含む）として保存する。実際のアカウント全体のNeurons残枠・請求額は未取得。無料上限時の例外もprovider_errorとして停止し、有料サービスに切り替えない。タイムアウトは結果待ちを打ち切るもので、プロバイダ内処理の取消しは保証しない。1試行/出力上限があるため当日再呼出しはしない。

ローカルでは模擬AIの単体テストとworkerdのservice RPC代替で、入力制限/再起動/停止中の応答破棄を検証する。実モデルの成功を示すものではない。2026-10-21の無害な64token REST probeは現API tokenで401、応答本文は非取得。Worker AI bindingとは別の認証経路なので、設定後の日次実行結果で確認する。
