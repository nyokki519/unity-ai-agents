# 運用記録と月次レポート

目的: 追加の外部取得/AI推論なしで、定期処理の実績と不明な日を見分ける。

実装単位:
1. 1日1件の運用記録をStateに保存。Dailyの実行状態/作成タスク数/対応するAI状態と、当該取得に結び付く集計だけ。自由文やモデル文章は含めない。
2. 最大90日分。勝手に古い記録を削除しない。上限または保存容量の余裕が不足すれば履歴の追記を止め、既存の最新取得/判定/AI処理は継続する。
3. 月次レポートは記録がある日の処理状態、記録のない日、AI生成記録、記録上のタスク作成数を表示する。日別の予約/実参加/PV累計を合算しない。最新の参照値を日時付きで示す。
4. UIは主要値→注意→詳細。月選択、Markdown保存。事実と固定文だけで、外部通知/公開を行わない。

過去の実行を推測しない。導入前の履歴は取得できた最後のDaily記録だけを条件付きで保存できる。取得に結び付かない古いsnapshotを新しい成功値として記録しない。実モデルの成功を模擬試験から推測しない。

検証: 日次重複/更新、失敗時の古い数値排除、90日上限/保存容量、同日再配信で確定データを失わない、未記録日の表示、月境界/JST/0/null/合計の誤用防止、スマホ/月選択/保存。

保存余裕の判定はState全体のJSON投影1,800,000 bytes。既存Stateの2MB上限を維持します。処理完了率の分母は成功・一部保留・失敗の記録日だけで、停止・見送り・未完了・未記録を含めません。日次レポートの作成タスク数とAI記録も保存済み実績だけです。AIの形式検証済みは提案の正しさや施策の効果を保証しません。

新しいDB、外部取得、AI呼び出し、月次の外部送信は追加していません。既存の日次処理が動けば記録が蓄積します。通常の画面更新では新しい日次履歴を作りません。
